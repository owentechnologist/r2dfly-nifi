# r2dfly status, 2026-10-28

This page is for whoever owns r2dfly next. It says what the project is for, what the
`redisshake-parity` work delivers, how to build and verify it, what is still open, and what will
trip you up. It is current to commit 05ecb80 on `main` (2026-10-29). For using r2dfly, start with
[the quickstart](quickstart.md).

## What r2dfly is

r2dfly is a set of Apache NiFi 2.x processors, and the bash scripts that deploy and drive them, for
migrating Redis and Valkey data into Dragonfly. `scripts/simple-migration.sh` runs a one-time copy.
`scripts/continuous-migration.sh` runs the copy and then keeps applying source changes until
`scripts/cutover.sh` says it is safe to switch. `scripts/headless-migration.sh` runs a one-time
copy with no NiFi server.

## The goal of this version

This version set out to make r2dfly the better choice than RedisShake for real migrations:
correct, recoverable, observable and safe to cut over, rather than only fast. The work was split
into packages WP0 to WP15. Every package followed the same rules, and new work should too:

- Java 21, as `artifacts/pom.xml` sets it, and NiFi 2.x APIs only.
- Lettuce is the client for normal commands. The replication reader uses the project's own
  replica client, `util/ReplicationStream`; `redis-replicator` was tried and rejected because it
  cannot read Redis 8's RDB version 15 and drops module commands.
- New dependencies must be Apache-2.0 or compatible.
- Keep existing processor names, relationships and scripts working. Mark replaced behavior as
  deprecated instead of removing it.
- Give every new setting a default, a description and a TOML key in the wrapper scripts.
- Never write to the source. PSYNC runs only when the user asks for it.
- Never stop the flow for one bad key. Every failure carries a reason in `redis.failure.reason`
  and lands in the dead-letter directory.
- Test every assumed fact. The results are in [verified behavior](verified-behavior.md).

## What it delivers

### The copy

- Each source shard is scanned once, with checkpoints in the NiFi map cache, so a restart
  resumes. The scan throttles itself on source latency or load and can read from replicas.
- A scan claim holds its owner's token. After a takeover, the old owner's next heartbeat fails and
  it stops, so two tasks never scan one partition.
- A slot that is still migrating when its shard's scan ends is read again on its owner once the
  migration settles.
- `RestoreProbe` tests each type and encoding against the target. Keys whose probe passes are
  copied with `DUMP`/`RESTORE`; the rest take the typed path in `RedisValueFetcher` and
  `CommandBuilder`.
- Module types follow the table in `util/ModuleCopy`: JSON and TopK are rebuilt, the rest are tried
  with RESTORE or dead-lettered with the reason. The default key types include every module type,
  so no key is skipped silently. Keys a user's type filter leaves out are counted by type in the
  run's summary.
- Large hashes and lists are split into chunks. Writers join a key's chunks within one batch
  (`util/ChunkReassembler`), so nothing is held in memory between triggers.
- Key names and values that are not UTF-8 text travel as base64 (`util/RedisBytes`, the
  `key_base64` and `base64` fields of `util/KeyRecord`), so they arrive byte for byte. Stream
  group and consumer names do too.
- Each reader records when it read a key's TTL (`redis.ttl.read.at`). The writer subtracts the
  time since, so a copy does not outlive its source key.
- A key whose `PTTL` fails is dead-lettered, not copied as never expiring.

### The live phase

- `--live-source keyspace` (the default) follows keyspace notifications. `--live-source
  replication` follows the source's replication stream through `util/ReplicationStream`, the
  project's own replica client, and resumes with a partial resync.
- The replication reader keeps one stream per cluster master and follows failovers, resharding and
  new shards. It refuses a connection pool that reads from replicas, because a replica lags.
- `MigrationReconciler` compares source and target key by key and repairs what no change stream
  reports, such as a `FLUSHDB`. Its Spare Target-Only Keys setting keeps target keys that no
  source key maps to. With `--live-source replication` it starts only once the reader's streams
  connect.
- A newer read of a key waits behind that key's pending retry, so an older value never lands on
  top of a newer one. The writer keeps these holds in its local state, so they survive a restart.
- `cutover.sh` reports LAGGING, NOT_SAFE, UNREVIEWED or SAFE, and with `--writes-stopped` it
  waits for the flow to drain and requires a clean full reconcile pass.
- `--live-source reconcile` runs reconcile passes as the only change source, which is how a
  reverse sync from Dragonfly back to Redis works: Dragonfly has no PSYNC and publishes only
  expiry notifications.

### Files and transforms

- `--source-rdb-file` and `--source-aof` load a file into a throwaway Redis container and copy from
  it. `--target-file` writes JSON lines (`KeyRecordFileWriter`), which `--source-file`
  (`KeyRecordFileReader`) loads back, or RESP commands, which also form an AOF.
- `--rename-prefix`, `--ttl-strategy` and database remap go through one mapping,
  `util/KeyMapping`, which every processor that writes, deletes, compares or indexes keys uses.
- `--transform-script` places NiFi's `ExecuteGroovyScript` in front of `RedisBatchWriter`.

### Without a NiFi server

- `scripts/headless-migration.sh` runs the one-time copy flow on NiFi's Stateless engine in the
  `apache/nifi` image. It reads a subset of `simple-migration.sh`'s TOML keys and rejects any
  other. `scripts/headless/HeadlessCopy.java` drives the engine until every scan partition is
  complete and nothing is queued. A run with no progress for five minutes ends with exit 3.
- `scripts/import-shake.sh shake.toml` translates a RedisShake 4.x config into an r2dfly TOML
  config and names the script to run it with. `--self-test` checks built-in cases.

### Observability

- Failures land in `/opt/nifi/nifi-current/r2dfly-dead-letter` inside the NiFi container (in
  `<work-dir>/dead-letter` for a headless run), one record per key, with the reason and the
  earlier reasons under `history`.
- Counters and gauges reach Prometheus through NiFi's `/nifi-api/flow/metrics/prometheus`.

## Measured against RedisShake

On an 8-CPU, 12 GB podman VM, Redis 7.4 to Dragonfly 2.0.2, in October 2026. Rerun any row with
`scripts/benchmark-vs-redisshake.sh`.

| Dataset | RedisShake `sync_reader` | r2dfly |
|---|---|---|
| 10 million strings | 63,700 keys/s | 38,300 keys/s |
| 1 million hashes | 77,900 keys/s | 37,100 keys/s |
| 10,000 lists of 1,000 elements | 5.1 s | under 1 s |
| Catching up after 60 s of mixed writes | 1,075 s | 328 s |

The bulk-copy gap was accepted: closing it needs many keys per FlowFile, which would rework the
per-key failure reasons, dead letters, RESTORE fallback and replication ordering. More concurrent
tasks made r2dfly slower on that machine, so the defaults stay at one task each.

## How to build and verify

The tests need a JDK and a container runtime. On the machine this was built on:

```bash
podman machine start dragon
export JAVA_HOME=/opt/homebrew/opt/openjdk PATH=/opt/homebrew/opt/openjdk/bin:$PATH
export DOCKER_HOST=unix://$(podman machine inspect dragon --format '{{.ConnectionInfo.PodmanSocket.Path}}')
export TESTCONTAINERS_RYUK_DISABLED=true
cd artifacts && mvn -o clean verify
```

The last recorded full run, on 2026-10-28 at commit bcb1427, passed 91 unit tests and 60
integration tests. Commits after it added integration tests, and no full run since is recorded.
Each integration test starts real Redis, Valkey, Redis Stack, Redis Cluster or Dragonfly
containers.

The Spare Target-Only Keys setting and the replication start order were verified end to end on
the AWS load-tester VM (rootless podman 3.4): scratch source and target published on the VM's
private IP, because podman 3.4 cannot join a running slirp4netns container to another network.

The scripts were verified end to end against a scratch NiFi: set `NIFI_CONTAINER_NAME` to a
scratch name and `NIFI_HTTPS_PORT=18443`, put scratch source and target containers on a private
podman network, and connect the NiFi container to that network once the script has created it.
Never point a test run at someone's own containers.

## Remaining work: WP12

WP12 makes r2dfly run from one command and lets RedisShake users bring their config with them.

- **Container image (item 9), open.** Publish an image that holds NiFi, the NAR and the flow
  definition, so one command runs a migration from one TOML file:
  `docker run ... r2dfly --config migrate.toml`. It can be built around the headless run.
  (`artifacts/toolbox/Dockerfile` is a helper image for the scripts, not this.)
- **Headless mode (item 10), done for one-time copies.** A continuous migration still needs a NiFi
  server.
- **`import-shake` (item 8), done.** `scripts/import-shake.sh` maps the readers, the writers,
  addresses, auth, `tls`, `cluster`, `dbs`/`allow_db`, `allow_key_prefix`/`block_key_prefix`,
  `allow_command_group`/`block_command_group` and `skip_unknown_type`. Command groups become real
  key-type filters, with a warning that explains the command-group trap below. Of the Lua
  functions in RedisShake's documented examples, it translates a prefix filter, a database move, a
  command-group filter and a prefix rewrite; a database filter or swap gets a manual note. It
  lists everything else for manual review, including `block_db`, `tls_config`, `sentinel` and any
  other Lua function, such as a type filter by RESTORE type byte.

The importer reproduces what RedisShake actually does, not what its docs suggest. These facts come
from reading RedisShake 4.7.0's source and running it against Redis 7.0 and Dragonfly 2.0.2:

- In the snapshot phase, `sync_reader` and `scan_reader` send each key as one `RESTORE`. Only a
  key whose dump exceeds `target_redis_proto_max_bulk_len` is split into typed commands followed
  by `PEXPIRE`.
- `RESTORE` is in the `GENERIC` command group, so `allow_command_group = ["HASH"]` silently drops
  every snapshot key. With `scan_reader` nothing is copied; with `sync_reader` only live writes
  arrive. This is the command-group trap.
- Filters run in this order, and all must pass: key rules (block, then allow), database, command,
  command group. A multi-key command such as `MSET` is dropped unless every key passes.
- `scan_reader` has an undocumented `skip_unknown_type` option that runs `TYPE` per key and skips
  the listed types. `sync_reader` has no such option.
- The Lua `function` hook sees `DB`, `CMD`, `GROUP`, `KEYS`, `KEY_INDEXES`, `SLOTS` and `ARGV`. A
  script that does not call `shake.call` drops the command without an error.

## Things that will trip you up

- **Stale classes.** An IDE compiler can leave class files in `target/`, and Maven then reports
  "Nothing to compile" for broken code. Always run `mvn clean verify`.
- **NAR reloads.** NiFi keeps the old classes of a NAR with the same SNAPSHOT coordinate until it
  restarts. `deploy-to-nifi.sh` restarts the container for that reason.
- **NiFi counters.** `/nifi-api/counters` lists each counter twice; skip the contexts that start
  with "All ". `recordGauge` values are not exported to Prometheus, so gauges are counters
  adjusted by their change (`util/CounterGauge`).
- **ExecuteGroovyScript.** Its properties are `Script File` and `Failure Strategy`. Older names
  such as `groovyx-script-file` are silently taken as dynamic properties. An exception a script
  does not catch stalls its whole batch, so scripts catch per record.
- **NiFi Stateless.** It never comes back for a penalized FlowFile, so a processor that penalizes
  hangs a headless run. Keep every penalty in the headless flow at 0.
- **Jackson.** A public `isX()` method marked `@JsonIgnore` hides field `x` from JSON as well.
- **Redis replication.** A Redis 8.10 master that has already selected database 0 can send later
  writes with no SELECT, also to a new replica. A master waits for a replica's first `REPLCONF ACK`
  before streaming after a diskless transfer.
- **Dragonfly 2.0.2.** It rejects DUMP payloads from Redis 8 and Valkey 9, and `XCLAIM IDLE` is
  wrong (use `TIME`). It accepts only `notify-keyspace-events Ex` and has no PSYNC. Lua scripts
  cannot touch undeclared keys unless it runs with `--default_lua_flags=allow-undeclared-keys`.
- **Shells.** The scripts must run on macOS's bash 3.2. `podman exec` mangles bytes that are not
  UTF-8 in command-line arguments, so seed binary test data as raw RESP on stdin.
- **Provenance.** NiFi's default provenance repository stalled every commit at migration volumes,
  so `deploy-to-nifi.sh` turns it off unless asked not to.
